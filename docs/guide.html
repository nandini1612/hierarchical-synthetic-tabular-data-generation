Project guide · deep dive

Constraint Repair for Hierarchical Synthetic Tabular Data

By Nandini Saxena and Snigdha Sarkar — closing the logical-validity gap in the H-TDBU framework of Nie, Jin & Chen (2026).

This guide explains the whole project end to end: the problem, the framework we build on, exactly what we added and why, how each mechanism works, the full experimental design, the results — including the finding that logical validity and statistical utility are separable — and where this is useful in practice.

01

Overview

Synthetic tabular data is usually judged on two things: how closely it matches the real data's statistics (fidelity) and how well a model trained on it performs on real data (downstream utility). Neither of these checks whether an individual synthetic row is internally coherent — whether its column values could co-occur in a real record at all.

We add a small, generator-agnostic detect-and-repair layer that (1) measures how many synthetic rows are logically impossible, and (2) repairs them to zero. Crucially, we build the repair two ways — one that borrows real data and one that does not — and use the contrast to show that fixing logical validity does not, by itself, improve downstream utility. Where it looks like it does, the cause is real-data leakage, not validity.

One-line result. Repair is a cheap, safe validity guarantee (impossible rows → 0% at ~1% compute overhead, no utility cost) — not a utility booster. Validity and utility are two separate problems needing two separate mechanisms.

02

The baseline framework (H-TDBU)

We build on Hierarchical Synthetic Tabular Data Generation: A Hybrid Top-Down and Bottom-Up Framework by Junfeng Nie, Alvin Jin, and Xiaohui Chen. It combines two paths:

  • Top-down (TD): domain rules and cross-modal alignment — e.g. a weak rule pairing a tabular target with the sentiment of attached financial-news text.
  • Bottom-up (BU): lightweight learned generators (Gaussian copula, RandomForest, XGBoost, plus neural CTGAN/TVAE baselines) that capture local statistical patterns from real seed data.

Synthetic data is then scored with TSTR (train-on-synthetic, test-on-real) utility, distributional fidelity, and — for the weak-multimodal benchmarks — XModal, a cross-modal alignment metric. The baseline's own headline finding, which we reproduced within seed noise, is that conditional tree-based generators (RandomForest, XGBoost) match or beat the neural baselines at far lower compute cost.

The unbuilt promise. The abstract names two top-down objectives: cross-modal alignment and "structure-driven logical constraints." Reading the code, only the first exists. Nothing checks a row's internal logical consistency. That is the gap we close.

03

The research gap: fidelity ≠ validity

Every existing metric evaluates columns individually or in aggregate. A row can therefore have a plausible value in every column while combining them impossibly. Consider one synthetic Bank Marketing record:

FieldValueMeansOn its own
pdays−1never previously contactedplausible
previous3contacted 3 times beforeplausible
poutcomesuccessa past campaign succeededplausible

You cannot have zero prior contacts and simultaneously three prior contacts and a past success. The record is impossible — yet fidelity, TSTR, and XModal all pass it silently. This matters wherever incoherent records carry risk: fraud detection and credit scoring trained on impossible rows can learn spurious patterns, and compliance/audit settings often need record-level coherence, not just statistical plausibility, to trust synthetic data.

04

Our contribution

  • A violation metric — a new violation_rate (overall and per-constraint) that exposes a failure mode the pipeline could not previously see.
  • A repair stage with three strategies (deterministic, k-NN, canonical) that drives impossible rows to exactly zero without discarding data.
  • A controlled experiment — running k-NN and canonical repair side by side, at identical validity, to separate the effect of logical validity from the effect of copying real data.
  • An interactive showcase where you can edit a row, generate a batch, and repair it live in the browser.

The layer is strictly additive — it modifies no baseline code — and does no machine learning: boolean checks, a similarity lookup, and a convergence loop.

05

Architecture

Repair is inserted as its own stage between synthesis and evaluation. Because it operates on plain dataframes, it is generator-agnostic — the same repair code runs identically after any upstream method, which also keeps the ablation clean (toggle repair on/off around any generator).

06

Methodology

6.1 Constraint design

Constraints are deterministic logical rules, not soft statistical correlations. Each is a vectorized boolean test over columns that returns a mask (True = violated). They encode real-world facts that must hold for a record to be coherent.

DatasetConstraintsNotes
Bank Marketing6 — pdays/previous/poutcome temporal consistency (×3), plausible age, positive campaign count, non-negative call durationno deterministic rule available; repaired by k-NN or canonical
Adult Income5 — education↔education_num (deterministic), relationship↔gender for Husband/Wife (deterministic), plausible age & hours-per-weektwo rules have an exact derivable answer
German Creditcategory-domain checks for coded columns + plausible age/duration/amountdeliberately conservative — Statlog codebook uncertainty

All constraint values (category domains, the education_num mapping) were verified against real sample rows from the actual processed data, not assumed.

6.2 Three repair strategies

Deterministic

When the correct value is uniquely forced by the row (e.g. education ⇒ education_num), apply the exact known value. A dictionary lookup — precise, one pass.

k-NN

When several repairs are valid, copy the offending columns from the nearest real record (standardized-Euclidean nearest-neighbour search). Minimally invasive — but injects real data.

Canonical

Fix the row from its own values with a fixed internally-consistent default (e.g. declare it "never contacted"). Same validity, no real data. The scientific control.

The deterministic and canonical fixes are conditional assignments and clamps; k-NN is a similarity search over an index of the real data (no trained model). None of them learns parameters.

6.3 Convergence loop

Constraints can share columns — the Bank Marketing temporal rules all touch pdays/previous/poutcome — so repairing one can transiently re-break another. The repair re-runs the full constraint sweep until no violations remain or a pass limit (default 3) is hit, so the reported "after" numbers reflect a settled state.

A design bug we found and fixed. The first temporal constraint originally repaired only previous/poutcome and left pdays untouched. Copying a "contacted-before" neighbour's history onto a still-pdays=−1 row re-created the violation — a stable ~6.5% plateau on Bank Marketing that 50 passes could not clear. Including pdays in the repaired columns (so the whole coherent triple is copied together) makes it converge to exactly 0% in 2 passes.

Experimental design

A three-way ablation isolates each mechanism's contribution across the grid 2 benchmarks × 3 generators × 3 repair modes × 3 seeds.

AxisValues
Benchmarksweak_multimodal (manual rule), weak_multimodal_gemini (LLM-generated rule); robustness on Adult Income, German Credit
Generatorsindependent (no structure), random_forest, xgboost
Repair modesnone, knn, canonical
Seeds42, 123, 2024 (the baseline's own seeds)
Metricsviolation rate (new), TSTR accuracy/F1/AUROC, XModal, fidelity

The neural baselines (CTGAN, TVAE) and Gaussian copula are out of scope here: the baseline's own reproduced finding is that RF/XGBoost already match or beat them, so testing repair against the strongest validated generators was the higher-value use of scope. Everything runs CPU-only. Full results are in data/processed/repair_ablation_v2/.

Results

Validity is solved

Impossible rows drop to exactly zero for every generator and repair mode. How many start impossible depends on how much column structure the generator preserves.

The key finding: the "utility boost" is leakage

On the weak independent generator, k-NN repair lifts TSTR AUROC — but canonical repair, at the same 0% validity, does not. Same validity, opposite effect. The movement is caused by k-NN copying real values in, not by logical validity.

Benchmarknonek-NNcanonicalvalidity (all)
weak_multimodal0.4890.592 (+0.10)0.448 (−0.04)0%
weak_multimodal_gemini0.5310.612 (+0.08)0.490 (−0.04)0%

Both fixers reach identical logical validity, yet k-NN "gains" up to +0.12 AUROC while canonical dips. Since validity is held constant, the entire difference is attributable to k-NN copying real data — leakage, not validity.

Free and safe on structured generators

On RandomForest and XGBoost, all three modes score identically within seed noise, and cross-modal alignment (XModal) is byte-identical before and after repair. There is no reason to ever turn repair off.

09

The correction (why we trust this)

An early Adult Income run used k-NN for a rule (education↔education_num) that is actually deterministic. It showed a large TSTR AUROC gain (+0.095) and never fully converged. The incomplete convergence was the tell: a rule with an exact answer was being approximated.

We added a deterministic_fix path, applied the exact value, and the gain collapsed to +0.004 — essentially zero. The original gain had been k-NN pulling in a whole real neighbour's coherence as a side effect. We then confirmed the same effect on Bank Marketing by adding the canonical arm, which reaches identical validity without touching real data. That turned "we suspect leakage" into a demonstration.

What changed in our claims. The finding "repair alone recovers utility" was withdrawn. The conservative, verified finding stands: precise repair does not reliably improve downstream utility on its own; its value is enforcing validity, at zero cost, without interfering with the generator's utility.

10

Limitations

  • Constraints are hand-authored per schema; they don't automatically scale to a new dataset without manual rule-writing.
  • German Credit's constraint set is deliberately conservative (category/range checks only) due to Statlog codebook uncertainty — a weaker robustness test than Adult or Bank Marketing.
  • Repair has only been tested downstream of tree-based / statistical generators, not LLM-based autoregressive generators (GReaT, TabuLa), which the literature notes have a weaker built-in guarantee of row-level structural consistency — the highest-value next test.
  • Canonical repair achieves validity but slightly distorts marginals (it over-concentrates the "never contacted" mode); so the precise claim is "utility change under repair is not driven by validity," not "canonical is a better generator."
11

Applications

Financial ML

Fraud detection and credit scoring trained on logically incoherent synthetic records risk learning spurious patterns; a validity gate removes impossible records before training.

Compliance & audit

Regulated settings often need record-level coherence, not just statistical plausibility, before synthetic data can stand in for real data in model development.

Privacy-preserving sharing

When sharing synthetic data instead of sensitive originals, a violation report is an auditable, human-readable quality signal — and the leakage finding is a caution: k-NN-style repair can smuggle real values back in.

Healthcare & records

Clinical and administrative records carry hard functional dependencies (dates, codes, counts) that statistical generators routinely break; deterministic repair fixes the derivable ones exactly.

Benchmarking generators

violation_rate is a new, orthogonal axis for comparing generators — it exposes structural weakness that TSTR and fidelity hide (independent sampling looks far worse under it).

Data cleaning, reframed

The detect-and-repair framing is borrowed from the integrity-constraint / denial-constraint data-cleaning literature, applied to synthetic rather than dirty real data.

Reproduce

# install
python -m pip install -r requirements.txt

# prepare processed datasets (place raw CSVs under data/raw/ first)
python src/main.py prepare

# baseline experiments
python src/run_experiments.py --datasets weak_multimodal,weak_multimodal_gemini,adult_income,german_credit \
  --methods independent,gaussian_copula,random_forest,xgboost --seeds 42,123,2024 \
  --n-rows 12000 --output-dir data/processed/experiments

# this work: 3-mode constraint-repair ablation (none / knn / canonical)
python src/run_repair_ablation.py --datasets weak_multimodal,weak_multimodal_gemini \
  --methods independent,random_forest,xgboost --seeds 42,123,2024 \
  --n-rows 12000 --output-dir data/processed/repair_ablation_v2

# robustness on Adult Income and German Credit
python src/robustness_check.py

Results land in data/processed/repair_ablation_v2/ as repair_ablation_results.csv (per dataset/method/repair_mode/seed) and repair_ablation_summary.csv (aggregated).

Glossary

TSTR
Train-on-Synthetic, Test-on-Real. Train a classifier on synthetic data, evaluate it on held-out real data. The primary downstream-utility measure.
TRTR
Train-on-Real, Test-on-Real. The real-data reference performance; TSTR is compared against it.
AUROC
Area under the ROC curve — how well a model ranks positive vs. negative cases (0.5 = chance). Robust to class imbalance, unlike raw accuracy.
Fidelity
How closely synthetic column distributions match real ones (mean/std differences, categorical total-variation distance).
XModal
Cross-modal alignment: the difference between real and synthetic joint distributions of the target and the attached text's sentiment.
violation_rate
Our metric: the fraction of synthetic rows violating one or more logical constraints.
Functional dependency
A rule where one column's value is uniquely determined by others (e.g. education → education_num) — repairable deterministically.

References & further reading

  • Baseline: Nie, Jin & Chen. Hierarchical Synthetic Tabular Data Generation: A Hybrid Top-Down and Bottom-Up Framework (2026). repo
  • Classical generators: Xu et al., CTGAN/TVAE (2019); Zhao et al. (2023) — GAN/VAE-learned distributions; no logical-constraint awareness.
  • Tabular diffusion: STaSy, SOS, TabDDPM — iterative denoising; same statistical-only focus, heavier compute.
  • LLM-based tabular synthesis: GReaT, REaLTabFormer, TabuLa — row-as-text autoregressive generation; does not guarantee functional dependencies between columns.
  • Adjacent field: constraint-based data cleaning / repair (functional dependencies, denial constraints) — the detect-and-repair framing this project borrows, applied to synthetic rather than dirty real data.
